1

Create the workshop environment

One CPU environment runs the data Jobs, the training Job, the model endpoint and the app. It needs Streamlit and a Python 3.12 compatibility fix that the standard environment lacks.

  • Participants select it by this name, and the guide refers to it by this name, so do not change the spelling.

  • The last two blocks matter. Python 3.12 removed a function that Domino's model-serving layer still calls, and without the fix the model endpoint never starts. The model API build also needs the image to end on the non-root user.

    Dockerfile instructions
    # Prerequisites for uWSGI
USER root
RUN apt-get update && apt-get install -y --no-install-recommends gcc && \
    apt-get clean && rm -rf /var/lib/apt/lists/*

ARG LDFLAGS=-fno-lto
ENV LDFLAGS=-fno-lto
ENV PYTHONPATH="${PYTHONPATH}:/mnt/code:/mnt"

# Packages used by the app and the EDA report
RUN pip install --no-cache-dir "setuptools<81" Flask Flask-Compress Flask-Cors uwsgi six prometheus-client ydata_profiling streamlit st-pages streamlit-extras "lxml[html_clean]"

# Python 3.12 removed configparser.SafeConfigParser; Domino's model-serving harness still calls it
USER root
RUN printf '%s\n' \
  'import configparser' \
  'if not hasattr(configparser, "SafeConfigParser"):' \
  '    class SafeConfigParser(configparser.ConfigParser):' \
  '        def readfp(self, fp, filename=None):' \
  '            return self.read_file(fp, filename)' \
  '    configparser.SafeConfigParser = SafeConfigParser' \
  > /opt/conda/lib/python3.12/site-packages/sitecustomize.py

# Model API builds need the image to end on the non-root user
USER ubuntu

  • If you edit the environment later, each save makes a new revision and the newest successful one becomes the active one. Older revisions are harmless history and do not need to be archived.

Create the GPU environment

A second environment adds the packages that serve and fine-tune the two open models. It builds on the first, so it must be built second.

  • Dockerfile instructions
    USER root
RUN pip install --no-cache-dir vllm transformers peft accelerate openai scikit-learn
USER ubuntu

  • The model weights themselves are not in the image. They download on first use into the participant project's dataset, so the cluster needs outbound access to Hugging Face, or the models must be mirrored to an internal registry (see the provenance note in the workshop guide).

3

Check hardware tiers

Participants choose from the hardware tiers you provide. Make sure the tiers below exist and are available to the workshop users.

  • Both open models run on one GPU. With 40 GB or more (for example an L40S 48 GB) the generator runs in full precision. A 24 GB card also works because the launcher loads the generator in 8-bit, at a small cost in quality. Smaller than 24 GB will not fit both models.

Plan GPU capacity by headcount

Each participant who reaches step 9 holds one GPU for the fine-tuning Job and again for the running app. A room of people at the same step can exhaust a small pool, so scale the node pool up beforehand, or let people take turns.

4

Code assistant environment optional

Build one environment that already contains the Cline extension (as a .vsix file), the Domino plugin for Cline and the tools it needs, so participants open a VS Code workspace and only paste in their own API key. Codex needs nothing extra: the Domino Standard Environment already includes the Codex extension, the Codex CLI and the Domino skills.

Some of this is a best guess

The steps follow the AI coding assistants setup guide and the usual Domino and code-server behavior. File locations marked "confirm" can differ by Domino version, so expect to adjust them after the first test in step 6. Domino 6.3 or Domino Cloud is assumed for the pre-installed Codex tooling.

4a. Gather the files

  • If your cluster cannot reach the internet during an environment build, put the file on an internal artifact server or file share that the build can reach, and use that URL below. Scan it and record its checksum as you would any binary you bring in.

4b. Create the environment

  • Participants then use this one environment for the whole workshop when they want an assistant. If you also want assistants in the GPU workspace, repeat this step with Fraud-Detection-LLM as the base.

  • Dockerfile instructions
    USER root

# 1. Cline extension as a .vsix file (swap in your internal URL if needed)
ARG CLINE_VERSION=<approved-version>
RUN mkdir -p /opt/vendor/vsix && \
    curl -fsSL -o /opt/vendor/vsix/cline.vsix \
      "https://open-vsx.org/api/saoudrizwan/claude-dev/${CLINE_VERSION}/file/saoudrizwan.claude-dev-${CLINE_VERSION}.vsix"

# 2. Domino plugin for Cline (swap in your internal mirror if needed)
RUN git clone --depth 1 https://github.com/dominodatalab/domino-cline-plugin.git /opt/vendor/domino-cline-plugin

# 3. uv, then pre-build the MCP server's Python environment
RUN pip install --no-cache-dir uv && chown -R ubuntu:ubuntu /opt/vendor
USER ubuntu
ENV UV_PYTHON_DOWNLOADS=never
RUN cd /opt/vendor/domino-cline-plugin/mcp-servers/domino_mcp_server && uv sync

  • The links go in the user's home folder, which is kept across restarts only when Home Directory Persistence is on. Running this script on every start rebuilds them either way, so participants do not repeat the plugin setup.

    Pre Run Script
    #!/bin/bash
P=/opt/vendor/domino-cline-plugin

# Cline extension, from the .vsix baked into the image (no internet needed)
code-server --install-extension /opt/vendor/vsix/cline.vsix \
  --extensions-dir ${HOME}/.local/share/code-server/extensions

# Domino skills, workflows, global rule and hook
mkdir -p ~/.cline/skills ~/Documents/Cline/Workflows ~/Documents/Cline/Rules ~/Documents/Cline/Hooks
for d in $P/skills/*/; do ln -sfn "$d" ~/.cline/skills/"$(basename "$d")"; done
for f in $P/workflows/*.md; do ln -sfn "$f" ~/Documents/Cline/Workflows/"$(basename "$f")"; done
ln -sfn $P/rules/domino.md ~/Documents/Cline/Rules/domino.md
ln -sfn $P/hooks/PostToolUse ~/Documents/Cline/Hooks/PostToolUse

# MCP server entry for Cline, only if the user has none (confirm the path on first test)
S=~/.local/share/code-server/User/globalStorage/saoudrizwan.claude-dev/settings
if [ ! -f $S/cline_mcp_settings.json ]; then
  mkdir -p $S
  cat > $S/cline_mcp_settings.json <<EOF
{"mcpServers":{"domino_server":{"command":"uv",
 "args":["--directory","$P/mcp-servers/domino_mcp_server","run","domino_mcp_server.py"],
 "env":{"UV_OFFLINE":"1","UV_PYTHON_DOWNLOADS":"never"}}}}
EOF
fi

  • The setting name and location depend on your Domino version, so look for it in the admin configuration. Codex does not need it, because Domino already saves ~/.codex.

  • The Open VSX download and the GitHub clone are needed only at environment build time, not for participants.

5

Oracle GPUs in a separate data plane optional

If the code assistants should use a model that runs on your own GPUs in Oracle Cloud, decide whether those GPUs are managed by Domino. If they are, they need a data plane and a hardware tier. If they are not, they need only a network path.

We do not know your environment yet

This step is written from assumptions and is meant to be refined with you as you go. Where a name or setting is a guess it is marked, and the questions at the end of the step are the ones to answer first. Send what you find back and we will fix the steps.

5a. Choose the pattern

PatternWhat it meansHardware tier needed?
A. Domino runs the modelDomino is installed or attached in the Oracle data plane. A model server such as vLLM runs on those GPUs as a Domino app, endpoint or Job, and the assistants call its URL.Yes. A data plane, a GPU node pool and a hardware tier in that data plane.
B. The model is hosted outside DominoYour team runs an inference service on the Oracle GPUs (for example on OKE or a GPU VM) and Domino only calls it over the network.No. Workspaces run on ordinary tiers. You need a reachable URL, a key and an egress rule.

The workspace that hosts VS Code does not need a GPU either way. The assistant is a client that sends requests to a model, so the GPU is needed only where the model itself runs.

5b. Pattern A: Domino-managed GPUs in the Oracle data plane

  • Guess: this is done under the admin settings for hybrid or remote data planes. Names vary by Domino version.

  • Tiers are grouped by data plane in the picker, so participants will see it under the Oracle data plane's name, not under Local. Give it a name that says what it is, such as oci-gpu-a10-24gb, and set which users and organizations may use it.

  • Cline works with any OpenAI-compatible endpoint. Codex expects the Responses API, so confirm your server version supports it, or use Cline for this model.

6

Test and hand off

Prove the environments work from a normal project before participants arrive, then tell them what to expect.

  • python .setup/verify_environment.py
  • nvidia-smi

  • If the extension or skills are missing, read the workspace's startup log for the Pre Run Script, then check the file locations marked "confirm" in step 4.

  • If GitHub is blocked, participants use the Domino-hosted option with the zip files instead. You can also copy the repository to an internal Git server and give participants that URL.

Participants no longer build anything

With the environments and tiers in place, participants only create a project, add the code and data, select an environment and run. If one cannot see an environment in the list, check its visibility (step 1, 2 or 4 above) first.
