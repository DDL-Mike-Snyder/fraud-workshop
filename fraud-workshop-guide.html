Hands-on workshop

Fraud Detection Workshop

Train a credit card fraud model as a Domino Job, inspect and register it, publish it as a REST endpoint, then put a web app in front of it. Every step is done in the Domino web interface, in a Domino-hosted project.

The path at a glance

The order below is the order you will work in. A model can only be registered from a finished training run, so the training Job comes before registration. The two data steps come first because the training script reads a file they create.

1

Get the project ready

Four things must be true before any Job runs: the code is in the project, the raw data is in the project's dataset, the compute environment has the right packages, and your files are synced.

  • If you received a code zip, upload it from the Code page, then open a workspace terminal in the project root and unzip it.

    unzip -o fraud-workshop-code.zip

  • Inside workspaces and Jobs, the dataset appears at /domino/datasets/local/<your-project-name>/. If you received a data zip instead, upload it to the dataset and run .setup/unzip_dataset.ipynb once to extract it in place.

  • The standard environment does not include Streamlit, which the app needs. The last block in the file is also required: Python 3.12 removed a function that Domino's model-serving layer still calls, and without the fix the endpoint in step 6 never starts.

    Dockerfile instructions
    # Prerequisites for uWSGI
USER root
RUN apt-get update && apt-get install -y --no-install-recommends gcc && \
    apt-get clean && rm -rf /var/lib/apt/lists/*

ARG LDFLAGS=-fno-lto
ENV LDFLAGS=-fno-lto
ENV PYTHONPATH="${PYTHONPATH}:/mnt/code:/mnt"

# Packages used by the app and the EDA report
RUN pip install --no-cache-dir "setuptools<81" Flask Flask-Compress Flask-Cors uwsgi six prometheus-client ydata_profiling streamlit st-pages streamlit-extras "lxml[html_clean]"

# Python 3.12 removed configparser.SafeConfigParser; Domino's model-serving harness still calls it
USER root
RUN printf '%s\n' \
  'import configparser' \
  'if not hasattr(configparser, "SafeConfigParser"):' \
  '    class SafeConfigParser(configparser.ConfigParser):' \
  '        def readfp(self, fp, filename=None):' \
  '            return self.read_file(fp, filename)' \
  '    configparser.SafeConfigParser = SafeConfigParser' \
  > /opt/conda/lib/python3.12/site-packages/sitecustomize.py

# Model API builds need the image to end on the non-root user
USER ubuntu
  • python .setup/verify_environment.py

  • A Domino Job runs the files saved in the project, not the files sitting in an open workspace. If you skip this, the Job in step 2 cannot find exercises/.

2

Prepare the data

The training script reads transformed_cc_transactions.csv, and it does not exist yet. Two short runs create it: a notebook that cleans the raw file, then a Job that builds the model features.

2a. Clean the data in a notebook

  • exercises/a_DataExploration/data_exploration_notebook.ipynb

  • Where to find them. In the JupyterLab file browser on the left (it starts at the project root), open artifacts, then a_data_exploration, and double-click a file to view it. The five files are correlation_heatmap.png, amount_distribution_by_class.png, fraud_rate_by_hour.png, top_features_correlation.png and categorical_fraud_analysis.png.

    The same folder appears on the project's Code page, under artifacts, once you sync your workspace changes (the next item). In a Domino-hosted project there is no separate Artifacts tab; artifacts are ordinary files in the project's artifacts folder. The CSV is not on the Code page: find it under Data, in the project's dataset.

2b. Build the model features as a Job

  • python exercises/b_DataEngineering/data_engineering.py
What this step does

It adds four columns (the amount compared with the 30-day average, a combined risk score, a trust score, and a generation label from age), scales the number columns and one-hot encodes the text columns. That is why the data grows from 19 columns to 43 (42 inputs and the label).

3

Run the model as a Job

Train the XGBoost fraud classifier on the transformed data. Everything it produces is recorded in Experiments.

  • python exercises/c_TrainingAndEvaluation/trainer_xgb.py

    Allow several minutes. After training, the script draws plots that refit the model many times (5-fold learning curves), which is the slow part.

  • python exercises/c_TrainingAndEvaluation/trainer_ada.py
python exercises/c_TrainingAndEvaluation/trainer_gnb.py
What the training script does

It reads transformed_cc_transactions.csv from the dataset, keeps rows that have a label, and splits them 80% for training and 20% for validation, keeping the same fraud share in both. It trains XGBClassifier(n_estimators=100, learning_rate=0.1, max_depth=4, subsample=0.8, colsample_bytree=0.8).

It records everything in a Domino experiment named "CC Fraud Classifier Training" followed by a short ID for you and your project. The run is named XGBoost. Logged items: 3 parameters, 17 metrics, three plots, a parameters file, a metrics file, a JSON result file, and the model itself under the name xgboost_model.

4

Inspect the results

Read the numbers and plots to judge the model, and see how Domino keeps the run, code and data together.

MetricHow to read it
roc_aucHow well the model ranks fraud above legitimate transactions. 1.0 is perfect; 0.5 is a coin flip. The headline number for comparing models.
pr_aucThe same idea, focused on the fraud class.
precision_fraudOf the transactions flagged as fraud, the share that really were.
recall_fraudOf the real fraud, the share the model caught.
f1_fraudOne number that balances precision and recall.
accuracyShare of all transactions classified correctly. About 36% of rows are fraud, so a model that always says "legitimate" would already score near 64%. Do not judge on this alone.
log_loss, brierHow good the probabilities are, not just the yes/no call. Lower is better.
tau_best_f1The score cutoff that gives the best F1 on the validation data.
inf_ms_rowMilliseconds to score one row, useful when thinking about serving.
One thing that can confuse you

All three training scripts write plots with the same file names into artifacts/, so the last script to run overwrites the earlier ones there. Each run's own copy is safe in its Artifacts tab in Experiments, so look there when comparing models.

6

Publish the model as an endpoint

Turn the registered model into a live REST API. The app in step 7 calls this endpoint to score transactions.

  • The window opens on the File and Function tab by default. Do not use that tab: it asks for a Python script, and this project does not have one. If you see a File box, you are on the wrong tab.

  • The token is not shown on the Overview page. Open the endpoint's Settings, then the Invocation tab, and generate an access token. Copy it as soon as it appears. A name such as workshop-app helps you recognize it later.

    The token is used as both the username and the password (HTTP basic authentication). The gear button next to a token revokes or regenerates it.

If the endpoint never starts

Open its logs. If you see no app loaded. GAME OVER together with configparser.SafeConfigParser, the environment was built without the last block of the Dockerfile in step 1. Add it, rebuild the environment, and publish the endpoint again.

7

Deploy the app

Publish the Streamlit app that sends a transaction to your endpoint and shows the fraud score.

7a. Give the app the endpoint details

  • NameValue
    xgboost_endpointThe endpoint URL from step 6
    xgboost_authThe access token from step 6

    The app also looks for adaboost_endpoint, adaboost_auth, gaussiannb_endpoint and gaussiannb_auth, for use if you published endpoints for the other two models.

7b. Publish the app

  • The menu has three options. Pick App from File, which runs a launch script stored in the project. Do not pick App in Workspace (it publishes from a live workspace session) or Agent (for the optional LLM add-on, not this workshop).

  • app.sh starts Streamlit on port 8888 and runs exercises/d_HostingAndExecution/app.py.

The page shows a form with the details of one card transaction: amount, customer age and tenure, risk and trust scores, location, time of day, transaction type, device, merchant category, channel, and a model picker. The app adds the same derived columns you created in step 2, converts the transaction into the 42 input fields the model was trained on, and posts it to your endpoint.

8

Check the real model answers

The app has a built-in fallback score, so a page that looks fine can still be skipping the model. Make sure the answer came from your endpoint.

How to recognize the fallback

The fallback counts how many of six simple rules a transaction trips (amount over 500, merchant risk above 1, device trust below −1, IP reputation below −1, distance above 2, and a night-time hour) and divides by six. Its only possible values are 0.00, 0.17, 0.33, 0.50, 0.67, 0.83 and 1.00.

The "ADA Boost" and "GaussianNB" choices use the fallback unless you published endpoints for those models and set their variables.
